# KnowEngine 演示手册

本演示包为「星驰汽车智能客服」场景准备了一套可直接入库的业务数据与知识库文档，
用于向他人完整演示 KnowEngine 的 **文档接入 → 智能切片 → 向量化 → 多源检索 → 意图路由 → 重排序 → 流式问答**
全链路能力，以及知识库运营侧的上传、切片、版本、权限、缓存审核等管理功能。

## 二、五分钟准备

### 步骤 1：确认服务在线

```bash
curl http://<host>:8009/health
```

预期返回 `status: UP`，并附带 Reranker 加载状态：

```json
{"status":"UP","reranker":{"available":true,"source":"env:RERANKER_MODEL_PATH","modelPath":"/app/model/model_quantized.onnx"}}
```

`available=false` 也能演示，此时重排序自动降级为 RRF 融合，正好可以讲「可插拔降级」这个设计点。

### 步骤 2：导入业务数据

**方式 A（推荐，不需要数据库密码）**：登录员工账号后调一次接口即可，服务端会执行内置的
`demo/demo-data.sql`：

```bash
# 1) 员工登录，拿到会话
curl -c /tmp/staff.txt -X POST http://<host>:8009/auth/staffLogin \
  -H "Content-Type: application/json" -d '{"empId":"TEST001","password":"123456"}'

# 2) 一键导入（幂等，可反复调用）
curl -b /tmp/staff.txt -X POST http://<host>:8009/api/demo/init-business-data
```

返回体里直接带三张表的实际数据作为校验：3 款车型、1 台车（`川A·88X5L`）、2 条订单。

**方式 B**（有数据库账号时）：`mysql -h <host> -u <user> -p know_engine < demo/sql/demo-data.sql`

脚本幂等（`ON DUPLICATE KEY UPDATE`），可反复执行。执行完会打印四段校验查询结果，
应能看到客户 `18650567815`、车辆 `川A·88X5L`、两条订单与三款在售车型。

### 步骤 2.5：切换「单车 / 多车」场景（演示选车卡片用）

系统对「售后维修 / 技术指导」类问题会做车辆绑定：**名下只有一台车时自动绑定，不打扰用户**；
**名下有两台车时才弹「请先选择车辆」卡片**。两个场景可以随时切换：

```bash
# 变成两台车 → 技术类提问必然弹出选车卡片
curl -b /tmp/staff.txt -X POST http://<host>:8009/api/demo/enable-multi-car

# 恢复一台车 → 演示「唯一车辆自动绑定」
curl -b /tmp/staff.txt -X POST http://<host>:8009/api/demo/disable-multi-car
```

默认状态是**一台车**（自动绑定）。要演示选车卡片，先切到两台车，再问一个技术类问题，
例如「空调不制冷了怎么排查」，就会收到：

```
[CARD]:请先选择车辆
[CARD_CHOICE_MYCAR]:[{"carId":"MYCAR-0001","fullName":"星驰 X5 2025款 尊享四驱版","plateNumber":"川A·88X5L",...},{...}]
```

前端点击某台车后会自动带上 `myCarId` + `carId` 重新提问，不会让用户再打一遍问题。

### 步骤 3：导入知识库

方式 A（推荐，一条命令）：

```bash
BASE_URL=http://<host>:8009 ./demo/import-knowledge.sh
```

脚本会用员工账号登录、逐篇上传并触发 SMART 切片，最后输出每篇文档的 `docId` 与分段数。
由 MinIO 内容去重机制保护，重复执行会跳过已存在的文档（打印「跳过（内容已存在）」）。

方式 B（界面操作，适合边讲边演示）：

1. 打开 `http://<host>:8009/staff-login.html`，用 `TEST001 / 123456` 登录
2. 进入 `upload.html`，逐篇上传 `demo/knowledge/*.md`
   - 知识库类型：`DOCUMENT_SEARCH`
   - 可见范围：前 5 篇选 `VISITOR`，`06-owner-benefits.md` 选 `OWNER`
3. 上传完成后在「文档切片设置」中选择：
   - 切片方式：`SMART`（智能切分，按 Markdown 标题做父子分段）
   - 最大分段长度：`300`
4. 点击「开始切片」，等待状态变为 `VECTOR_STORED`

> 采用 300 字长度是为了让每篇文档里「超过 300 字的小节」自动产生**父分段 + 子分段**，
> 演示时可以在分段列表里直观看到 `skip_embedding=1` 的父块与带 `parent_chunk_id` 的子块。
> 若希望分段更少更整，可改用 `500`。

### 步骤 4（可选）：导入图数据

```bash
cypher-shell -a bolt://<host>:7687 -u neo4j -p <password> -f demo/cypher/demo-graph.cypher
```

图数据的 `CarVersion.infoId` 与 `car_info.info_id` 完全一致（`CAR-X5-2025` 等），
便于讲解「同一个车型在三类数据源中如何对齐」。

## 四、用例详解

### 路线 A：客户问答体验

> **前提**：演示账号名下必须有一台车（`my_car` 表中 `user_id = 该账号 id`）。
> 只有一台车时系统会**自动绑定**，直接回答；有两台及以上才会弹「请先选择车辆」卡片。
> 没有车时返回 `[WARN]:您还没有添加车辆信息`，此时执行 `demo/sql/demo-data.sql` 即可。

#### A1 登录与鉴权隔离

- **操作**：未登录直接访问 `http://<host>:8009/api/chat/list`
- **预期**：HTTP `401`，返回 `{"code":401,"message":"未登录或登录已过期"}`
- **机制**：Sa-Token 拦截器 + 全局异常处理把 `NotLoginException` 映射为 401，前端据此跳转登录页
- **讲解点**：接口不做裸奔，前后端约定 401 统一跳登录；页面与接口分离，静态页可公开访问

#### A2 非汽车问题不检索（意图前置拦截）

- **提问**：「今天适合钓鱼吗？」
- **预期**：正常闲聊式回答，**没有**「正在改写问题/检索」等进度，也**没有引用来源**
- **机制**：意图识别输出 `related=false`，链路直接走通用对话模型，跳过整个 RAG 管道
- **讲解点**：不是所有问题都值得走向量检索，前置意图判定能显著降低时延与无效检索

#### A3 技术指导：仪表警示灯（知识库主链路）

- **提问**：「我的车是川A·88X5L，仪表盘上电池图标变红是什么意思？」（车辆可自动绑定，无需编号）
- **预期**：
  1. 依次出现进度：识别意图 → 改写问题 → 路由问题 → 排序筛选 → 生成回答
  2. 回答包含「立即靠边停车、关闭空调、禁止泼水降温、联系救援」等要点
  3. 末尾出现引用来源，命中《星驰 X5 智能座舱与仪表警示灯使用指南》
- **机制**：意图=`车辆使用与技术指导` → 路由到知识库检索 → ES kNN（bge-m3）+ 全文检索 → RRF → BGE Reranker 精排 → 注入 prompt
- **讲解点**：引用可溯源；回答严格来自文档，文档没写的会明确说「暂无资料」而不是编造

> 账号名下只有一台车时，系统会自动把它绑定到本次提问，既跳过选车卡片也解锁 OWNER 文档；
> 详见「六、已知限制」第 1 条。

#### A4 售后政策：保养价格与三包

- **提问**：「X5 两万公里保养要多少钱？三包有效期是多久？」
- **预期**：
  - 2 万公里保养套餐 1,680 元，另加工时费 200 元，合计 1,880 元
  - 三包有效期 2 年或 5 万公里（以先到为准），包修期 3 年或 6 万公里
- **机制**：命中 `02-after-sales-warranty.md` 的「保养周期与保养项目」「三包有效期」小节
- **讲解点**：同一篇文档被切成多个语义段，问题跨两个小节时能同时召回并合并回答

#### A5 售前导购：三款车怎么选

- **提问**：「家里有两个孩子，平时市区通勤，偶尔跑长途，S3、X5、M7 怎么选？」
- **预期**：按「有家充桩选纯电、无家充桩选增程、经常满载跑高速选插混」给出建议，
  并结合二排零重力座椅、七座布局推荐 M7
- **机制**：意图=`售前咨询与购买`，使用售前专用 prompt，回答偏导购语气而非工程师语气
- **讲解点**：同一份知识库，不同意图走不同系统提示词，回答风格随之切换

#### A6 投诉维权：退车补偿费怎么算

- **提问**：「新车三个月修了两次还没修好，我要退车，要扣我多少钱？」
- **预期**：给出公式 `车价款 × 行驶里程 ÷ 1000 × 0.5%`，并按 35.8 万、12,860 公里算出约 23,019 元，
  同时说明需先满足「同一严重安全故障累计修理 2 次仍未排除」等条件
- **机制**：意图=`投诉与维权`，路由到投诉规范文档，prompt 切换为安抚+规则口径
- **讲解点**：涉及金额与法规的场景最怕模型胡编，RAG 把口径锁死在文档里

#### A7 结构化查询：我的保险/订单（Text2SQL）

- **提问**：「我的车保险还有多少天到期？」「我那个保养订单付钱了没？」
- **预期**：
  - 保险到期日 `2027-03-14`，并给出剩余天数
  - 保养订单 `XC20261020008` 状态「待支付」，金额 1,880 元
- **机制**：路由判定 `relational_db` → LLM 生成 SQL → 直连 MySQL 查询 → 结果作为上下文交给模型组织语言
- **讲解点**：结构化问题不该走向量检索；路由把「语义问题」和「数值问题」分开处理

#### A8 图查询：车型与配件关系（需导入图谱）

- **提问**：「你们现在有哪些纯电车型？」「X5 和 S3 用的轮胎是同一款吗？」
- **预期**：纯电车型返回 S3；共用配件返回两车都使用 `米其林轮胎 255/50 R20`
- **机制**：路由判定 `graph_db` → Text2Cypher → Neo4j 查询；图谱不可用时自动回退到向量检索
- **讲解点**：多跳关系查询用图数据库，比让大模型在文本里「找关系」可靠得多

### 路线 B：知识库运营

#### B1 上传与智能切片

- **操作**：`upload.html` 上传 `05-charging-guide.md`，选 `SMART` + 300
- **预期**：上传成功后状态 `CONVERTED`，切片后 `CHUNKED`，向量化完成后 `VECTOR_STORED`
- **讲解点**：状态机 `UPLOADED → CONVERTING → CONVERTED → CHUNKED → VECTOR_STORED`，
  向量化由 Spring 事件在事务提交后异步触发，不阻塞上传接口

#### B2 父子分段可视化

- **操作**：`document.html` → 某篇文档「查看分段」
- **预期**：能看到小节级别的分段；超过 300 字的小节会额外出现一条 `skip_embedding=1` 的父块，
  以及若干带 `parent_chunk_id` 的子块；点「Meta 信息」可看到 `title`、`subtitle`、`header_level`
- **讲解点**：检索用小块保证精度，喂给大模型用父块保证上下文完整，这就是父子分段的价值

#### B3 分段编辑与即时生效

- **操作**：编辑某条分段的正文并保存
- **预期**：保存后该分段重新向量化，再次提问时答案随之变化
- **机制**：`SegmentEditedEvent` 触发单条重嵌入，不需要重建整篇文档

#### B4 版本管理

- **操作**：对 `02-after-sales-warranty.md` 上传 `1.1.0` 版本（例如把保养价格改掉）→ 版本列表 → 切换版本
- **预期**：切换后旧版本分段降级为 `STORED`、ES 向量清理，新版本重新向量化；提问能得到新价格
- **讲解点**：知识库不是一次性导入，版本可回滚、可灰度，旧版本失效时向量同步清理

#### B5 权限隔离

- **操作**：分别用「名下有车的客户」和「没有车的账号」提问「首任车主终身质保需要满足什么条件？」
- **预期**：有车账号能召回（`06-owner-benefits.md` 为 `OWNER` 权限）；
  无车账号**答不出来**或只给通用回答
- **机制**：`UserRoleService` 依据「是否拥有该车辆」判定 `OWNER`，检索时用 `metadata.accessibleBy` 过滤
- **讲解点**：权限不是靠提示词约束，而是在向量检索的 filter 层做的硬隔离。
  若只有一个账号，可临时把 `my_car` 那行删掉再试，验证完再插回

#### B6 问答缓存审核（需开启开关）

- **前置**：环境变量 `QA_CACHE_ENABLED=true`，重启服务
- **操作**：
  1. 新建 **3 个会话**，每个会话的**第一句话**都问「两万公里保养多少钱」，回答要有引用来源（这是挖掘的硬条件）
  2. 员工登录后访问 `GET /api/qa-cache/curate` 触发整理（正式环境由定时任务调用）
  3. 打开 `qa-cache.html`，在 `PENDING` 列表审核 → 通过 → 发布
  4. 再问一次同样的问题，观察响应明显变快，且不再走检索
- **讲解点**：高频问题沉淀为标准答案，既是性能优化也是知识治理；发布前必须人工审核

### 路线 C：技术架构

#### C1 混合检索与融合排序

- **讲解**：一次提问并行走 4 路检索器 —— 向量（kNN）、全文（BM25）、SQL（结构化）、图（Cypher），
  路由先决定用哪几路；结果经 RRF 融合，再用本地 BGE-Reranker-v2-m3 精排，`minScore=0.6` 过滤后取 Top5
- **可观察点**：进度条依次出现「改写问题 → 路由问题 → 排序筛选」，说明各阶段在做什么

#### C2 重排序可插拔降级

- **操作**：`curl /health` 查看 `reranker.available`
- **讲解**：模型文件存在则加载 570MB 的 ONNX 做精排；不存在则记一条告警并降级为 RRF 融合，
  服务照常可用 —— 大模型依赖不应该成为启动的硬门槛

#### C3 流式输出与可观测

- **讲解**：SSE 逐 token 推送，`[PROGRESS]`、`[REFERENCE]`、`[CARD]`、`[DONE]` 等事件与正文分离；
  助手消息落库，刷新页面后历史仍在

## 六、已知限制（演示时请规避）

1. **选车卡片的触发条件**
   卡片只在「售后维修与保养 / 车辆使用与技术指导」意图、`car_id` 为空、且账号名下有
   **两台及以上**车辆时出现。名下仅一台车时会自动绑定、不打断问答。
   演示卡片前先调 `POST /api/demo/enable-multi-car` 加第二台车（见「步骤 2.5」）。
   另外营销类问题若未指明车型，会弹出「请选择车型」卡片（数据源是 `car_info` 表）。

2. **Text2SQL 未按登录用户过滤**
   SQL 检索器生成的是全库查询，不带 `user_id` 条件。单客户演示数据下结果正确，
   多客户环境下会串数据。生产化时需在 `KnowEngineSqlDatabaseContentRetriever` 注入当前 userId。

3. **表结构描述包含敏感表**
   `buildDatabaseStructure()` 把整份 `tables.sql` 塞进 Text2SQL prompt，其中包含
   `user_info`、`staff_info` 的密码列。建议改为白名单表（`car_info`/`my_car`/`car_order`）。

4. **`OWNER` 权限依赖 `car_id`**
   权限判定走 `getCarByUser(car_id, userId)`，`car_id` 为空时一律按 `VISITOR` 处理，
   因此 OWNER 文档在普通提问下检索不到，属设计如此，不是 bug。

5. **问答缓存默认关闭**
   `QA_CACHE_ENABLED` 默认 `false`，`/api/qa-cache/*` 会返回 503。演示 B6 前需显式开启。

6. **Neo4j 未就绪时自动降级**
   图检索器构造失败会被吞掉（`log.warn`），链路继续走 ES + SQL，不会 500，但 A8 用例无效果。

7. **文档内容去重**
   上传按内容 MD5 去重，同一份文件重复上传返回 409「文档内容已存在，请勿重复上传」。
   要重演上传流程，需先在 `document.html` 删除旧文档（会级联清理分段与 ES 向量）。

## 七、复位与排障

**重新演示一遍**

1. 员工登录 → `document.html` → 勾选演示文档 → 批量删除（同时清理分段与向量）
2. 重新执行 `./demo/import-knowledge.sh`
3. 会话记录可在 `chat.html` 左侧列表逐条删除，或直接改 `chat_conversation`/`chat_message`

**导入后提问查不到内容**

| 检查项 | 方法 | 期望 |
| --- | --- | --- |
| 文档是否切片 | `document.html` 看状态 | `VECTOR_STORED` |
| 分段是否有向量 | 查看分段列表条数 | 每篇 10~20 条 |
| ES 索引是否有数据 | `GET know-engine-vector/_count` | 与分段数相当 |
| 意图是否被判定为不相关 | 观察有无「改写问题」进度 | 有进度说明进了 RAG |
| 是否被车辆校验拦截 | 回答是否为「您还没有添加车辆信息」 | 若有，说明 `my_car` 未导入或 `user_id` 不匹配 |
| 检索到了但回答「没有相关资料」 | 看服务日志 `[检索] 命中=` 与 `[重排序] 候选=/保留=` | 命中 > 0 且保留 > 0，说明问题在权限过滤或索引 mapping，见下节 |

**⚠️ 重建向量索引前必读（踩过的坑）**

`know-engine-vector` 索引里 `metadata.accessibleBy` **必须是 `text` + `keyword` 子字段**，
不能只建成 `keyword`。原因：LangChain4j 的 `ElasticsearchMetadataFilterMapper.formatKey()`
对所有字符串类型的过滤值会自动拼成 `metadata.accessibleBy.keyword`，
如果索引里没有 `.keyword` 子字段，权限过滤会命中 0 条，
表现为「ES 里明明有向量、单独查能查到，但问答永远说没有相关资料」。

自定义 mapping 时请保持：

```json
"accessibleBy": { "type": "text", "fields": { "keyword": { "type": "keyword", "ignore_above": 256 } } }
```

重建后可用下面这条命令自检（把 `<embedding>` 换成任意一条查询向量）：

```bash
curl -s "http://<host>:9200/know-engine-vector/_search" -H 'Content-Type: application/json' -d '
{"knn":{"field":"vector","query_vector":[<embedding>],"k":5,"filter":{"term":{"metadata.accessibleBy.keyword":"VISITOR"}}}}'
```

返回 5 条才算正常；返回 0 条就说明 mapping 建错了。

**`/health` 里 `reranker.available=false`**

模型文件没挂载上。检查容器内 `/app/model/model_quantized.onnx` 是否存在，
或通过 `RERANKER_MODEL_PATH` 指到实际路径。此状态下问答仍可用，只是精排降级。
